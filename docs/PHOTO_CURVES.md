# Photo-traced visible curves

Evidence → Locate a point from three photos → Trace a visible curve reuses the production three-view point solver. Select the same visible point in three translated images, Check and add curve point, then repeat along the visible section. The first two views fit each sample and a third independently checks it. Neighboring samples need at least two shared source photographs. Undo curve point removes the last sample. Saving requires two to 128 samples and explicit confirmation that each joining interval is visible. Start a separate curve across an occluded section; crossings do not create graph connections.

The resulting feature contains point geometry, an ordered route and one original-source control track per vertex. No depth buffer supplies its geometry. Every point retains the existing 10 cm baseline, 5 degree fitting parallax, 15 mm ray disagreement, two-pixel reprojection and 0.15–8 m range admission. These are conditioning/residual checks, not calibrated accuracy bounds. Original photographs, camera estimates and depth remain immutable. Changing the source fingerprint invalidates the derived curve.

The app and offline archive viewer render a line stroke with no metric radius. GLB exports LINE_STRIP with the original per-point photograph controls in extras and explicitly unknown envelope. Reduced point previews do not connect skipped samples. Complete archives preserve editable route/track metadata; semantic CSV retains ordered route points and endpoint/source records. Geometry-only PLY/OBJ and this build's USDZ point profile retain samples but do not advertise a reconstructed cable/pipe envelope. Existing manually traced mesh routes retain their prior representation.

The prepared native check uses foreground points 0.75–0.8 m ahead of the synthetic depth surface, verifies three independent tracks and archive preservation, rejects a disagreeing third view, one-point curve, limited tracking, disjoint neighboring source views and unconfirmed intervals, and checks registered line geometry. An independent Khronos/fixed-frame reader checks the exported GLB; a local-file Chromium/WebGL check requires a visible line with no network requests. Neither publishes the raw fixture. The existing point UI flow is extended to select/save two curve samples. Exact-source native/UI/reader validation is pending.

This is a manual visible-centerline tool. Automatic correspondence/curve recovery, pipe/duct envelopes, uncertain occluded continuation, calibrated uncertainty and varied-house thin-service completeness remain open. No physical precision qualification is implied.
