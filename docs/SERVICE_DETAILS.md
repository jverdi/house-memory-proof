# Recorded service details

Object details supports a typed service class, observed label, panel and circuit references, cable category, endpoint, port, conduit-size description, pipe/duct-envelope description, installation date, associated boundary, identity confidence and evidence notes. Room and construction stage remain the object's existing references. Empty fields are unknown. Older archives without `service` decode unchanged; the old combined endpoint text remains available and is never guessed into the new fields.

Taxonomy includes structure/blocking, electrical power, low voltage, plumbing supply/drain/vent, HVAC supply/return/exhaust, insulation, fire-stopping and access points. These recorded classes complement the scene's system filter. Classification never creates a route connection or changes measured geometry. A recorded size is text with its stated units, not a reconstructed diameter or calibrated envelope. Owner-confirmed identity requires evidence notes; it does not qualify spatial precision or prove that an unseen route is continuous.

Every text field is limited to 4,096 UTF-8 bytes and excludes NUL. Installation dates use a real Gregorian `YYYY-MM-DD` calendar date, with no invented time or timezone. Boundary references must resolve to the object's room and construction stage. Native project admission and the independent archive reader enforce these constraints. CSV's existing `provenance_json` preserves typed fields without changing its 39-column v1 contract; the generic CSV reader validates them. GLB includes `serviceDetails` extras. Complete archives retain the original semantic records.

Indexed evidence search includes these fields, the boundary name, feature UUID and construction-stage date in addition to room, system, endpoint and notes. Single-object saves retain the existing stale-editor comparison. Unsaved changes block accidental swipe dismissal.

Evidence → Classify objects supports explicit multi-object selection, text filtering and bounded result pages. It saves system and service class as one project revision, increments each changed object's revision and preserves other metadata, original geometry and endpoint connections. It captures the opening snapshot and refuses the entire operation if any selected object changed. Tools → Restore previous local revision can undo the batch. Changes to other objects are preserved.

Validation prepared: native legacy/unknown decoding, calendar and UTF-8 rejection, missing/cross-stage boundary rejection, evidence search, archive restore, atomic stale-batch refusal and revision undo; independent archive/CSV checks; interface edit/save/relaunch/search. Exact-source native and interface evidence is required before marking this path verified. This does not close automatic thin-service reconstruction, spatial uncertainty, physical sensing or whole-house qualification.
